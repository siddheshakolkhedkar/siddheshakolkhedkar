## About

I am a Mechanical Engineering student at **NIT Trichy** building toward a career in **software engineering, AI/ML, and data-driven product development**.

My work sits at the intersection of **software engineering and machine learning**: designing clean data pipelines, implementing ML systems, experimenting with model architectures, evaluating results quantitatively, and turning prototypes into usable engineering workflows.

I care about more than getting a model to run. I focus on understanding the **problem, the data, the architecture, the trade-offs, and the failure modes** behind the system. My current work spans **machine learning, NLP, computer vision, SQL, backend development, and DSA**, with an increasing focus on building production-oriented systems rather than isolated notebooks.

I am particularly interested in:

- Software engineering for AI-powered products
- Applied machine learning and intelligent systems
- NLP and Transformer architectures
- Computer vision and image processing
- Data analytics and SQL-driven decision systems
- Backend and full-stack application development
- Product engineering with measurable outcomes

<summary><strong>Transformer From Scratch — Emotion Classification</strong></summary>

### Transformer From Scratch — Emotion Classification

A minimal Transformer-based NLP system built to understand the internal mechanics of sequence classification rather than relying entirely on high-level pretrained pipelines.

| Metric | Details |
|---|---|
| **Stack** | Python · PyTorch · NumPy · pandas · scikit-learn · Matplotlib |
| **Scale** | DailyDialog dataset with multi-class emotion labels |
| **Performance** | Training and validation pipeline with Accuracy, Macro-F1 and Confusion Matrix evaluation |
| **Security** | Local dataset processing with dependency isolation and environment-based configuration |
| **Impact** | Demonstrates understanding of Transformer components, training dynamics, class imbalance and evaluation |
| **Repository** | [GitHub](https://github.com/siddheshakolkhedkar/NLP) |

### Engineering Scope

- Implemented a minimal Transformer-style architecture for text classification.
- Built the complete preprocessing and training pipeline around the DailyDialog dataset.
- Added class-weighted loss to address severe class imbalance.
- Added validation metrics beyond raw accuracy.
- Generated classification reports and confusion matrices for error analysis.
- Investigated model performance instead of treating training loss as the only success metric.

</details>

<details>
<summary><strong>Object Boundary Tracker — Computer Vision</strong></summary>

### Object Boundary Tracker

A classical computer vision pipeline for detecting and tracking the boundary of an object across image frames using image preprocessing, edge detection, contours and centroid-based tracking.

| Metric | Details |
|---|---|
| **Stack** | Python · OpenCV · NumPy |
| **Scale** | Frame-by-frame image/video processing |
| **Performance** | Real-time-oriented contour detection and centroid tracking pipeline |
| **Security** | Local computer vision processing without external inference APIs |
| **Impact** | Demonstrates practical understanding of image preprocessing, edge detection and object localization |
| **Repository** | [GitHub](https://github.com/siddheshakolkhedkar/Object_boundary_tracker) |

### Engineering Scope

- Converted frames to grayscale to simplify edge analysis.
- Applied preprocessing and Canny edge detection to identify object boundaries.
- Used contours to isolate candidate object regions.
- Targeted the largest closed contour as the primary object boundary.
- Computed object centroids for frame-to-frame tracking.
- Debugged background tracking and contour instability through iterative preprocessing changes.

</details>
